# 한키 0.2.1-rc.1 호환성 안내

이 후보는 “한키는 실행 중이고 설정도 켜져 있지만 문구가 변환되지 않음”을
현장에서 분류하기 위한 진단 빌드다. 실제 PC방 재검증 전이므로 특정 보안
제품, 관리자 권한 또는 IME를 원인으로 확정하지 않는다.

## 5분 현장 확인

1. `Hanki-0.2.1-rc.1-win-x64-portable.zip`을 새 폴더에 푼다.
2. `Hanki.exe`를 실행하고 **호환성 진단** 탭을 연다.
3. **키 입력 감지 자가 테스트**를 누른 뒤 8초 안에 아무 키나 한 번 누른다.
4. 종결자를 Space로 선택하고 **임시 테스트 준비**를 누른다.
5. 아래 입력창에 `;hankitest`를 입력하고 Space를 누른다.
6. 일반 메모장과 문제가 발생한 프로그램에서 실제 단축어를 한 번씩 확인한다.
7. 각 외부 프로그램 결과를 성공/감지 후 입력 실패/아무 반응 없음 중 하나로
   고른다.
8. **진단 ZIP 내보내기**로 파일을 저장한 뒤 한키를 완전히 종료한다.

임시 단축어는 실제 목록이나 데이터베이스에 저장되지 않으며 2분 뒤 또는
한 번의 일치 시도 후 제거된다.

## 진단 결과 읽는 법

### 키 입력 자가 테스트 실패

- 후크 등록 상태와 전용 스레드 상태를 먼저 확인한다.
- **후크 다시 등록**은 최대 3회의 제한된 백오프를 사용한다.
- 등록 실패 또는 키 감지 없음은 관찰된 사실이다. 보안 프로그램 차단을
  확정하려면 현장 정책과 보안 제품 기록이 추가로 필요하다.

### 내부 테스트 성공, 외부 앱 실패

- 한키 후크와 기본 변환 로직은 동작한다.
- 대상 앱의 무결성 수준, 입력 문맥, 민감/읽기 전용 판정, 제외 목록,
  단계별 주입 수를 확인한다.
- 대상이 더 높은 권한이면 Windows UIPI가 입력을 제한할 가능성이 높다.

### 단축어 감지는 성공했지만 입력 실패

- 마지막 처리 결과의 삭제·변환문·종결자 수를 확인한다.
- 삭제만 성공하고 본문이 실패한 경우 Ctrl+Z로 복구할 수 있는지 확인한다.
- 한키는 부분 실패를 성공으로 집계하지 않고 사용 횟수도 증가시키지 않는다.
- 같은 실패를 자동 무한 재시도하지 않는다.

### 아무 반응 없음

- 자가 테스트도 실패하면 후크 또는 현장 입력 정책 가능성을 우선 확인한다.
- 자가 테스트는 성공하지만 후보 감지 기록이 없으면 종결자 설정, 수정키,
  IME 조합, 포커스 이동을 확인한다.
- 후보 기록 뒤 `InputContextUnavailable`이면 해당 컨트롤이 UI Automation
  텍스트 문맥을 제공하지 않는 것이다.

## 환경별 기대 동작

### 일반 데스크톱 앱

UI Automation `TextPattern`과 일반 키보드 입력을 제공하는 메모장·WPF
TextBox 계열이 기본 대상이다. 단축어 앞은 문자열 시작 또는 공백 경계여야
한다.

### 관리자 권한 앱

일반 권한 한키보다 대상의 무결성 수준이 높으면 Windows UIPI가
`SendInput`을 제한할 수 있다. **이번 세션만 관리자 권한으로 한키 다시
시작**은 사용자가 직접 눌렀을 때만 UAC를 요청한다.

- 자동 관리자 실행을 설정하지 않는다.
- Windows 시작 프로그램을 관리자 권한으로 강제하지 않는다.
- 현재 설정과 로컬 데이터 경로를 유지한다.
- 관리자 실행이 게임·PC방 보안 정책을 해제한다고 보장하지 않는다.

### 게임과 게임 보안 모듈

한키는 DLL 주입, 프로세스 핸들 강제 조작, 안티치트 우회, 드라이버 설치,
보안 정책 비활성화를 사용하지 않는다. 게임이 일반 텍스트 접근성 컨트롤을
제공하지 않거나 합성 입력을 제한하면 한키가 동작하지 않을 수 있다.

### PC방 보안 환경

현장 보안 프로그램은 전역 후크 등록, UI Automation, 합성 입력, 클립보드
붙여넣기를 각각 제한할 수 있다. 진단 ZIP과 화면 결과로 어느 단계까지
도달했는지 확인하되 제품명을 원인으로 추측하지 않는다.

### 원격 데스크톱

`mstsc.exe`는 기본 제외 목록에 있다. 원격 세션과 로컬 세션의 입력 경계가
불명확해질 수 있으므로 사용자가 명시적으로 제외 목록을 바꾸기 전에는
변환하지 않는다.

### Windows 보안 화면

로그온, 자격 증명, UAC 동의, 잠금 화면 등 보호 프로세스와 보안
데스크톱에서는 변환하지 않는다.

### 비밀번호 입력창

UI Automation `IsPassword=true`인 요소는 `SensitiveField`로 차단한다.
클립보드 호환 모드가 켜져 있어도 동일하게 차단한다.

## 종결자와 IME

- Space, Enter, 숫자패드 Enter, Tab을 서로 다른 종결자로 기록한다.
- Ctrl·Alt·Windows 키 조합 중인 종결자는 무시한다. Shift는 허용한다.
- 한글 IME 조합 문자열이 남아 있으면 변환을 보류해 조합을 훼손하지 않는다.
- 키보드 레이아웃은 KLID 형태의 식별자만 기록하고 입력 문자는 기록하지 않는다.
- Caps Lock과 Num Lock 상태는 진단에 포함한다.
- OEM 세미콜론 등 단축어 문자는 UI Automation 문맥에서 실제 문자로
  비교하므로 현재 레이아웃 결과를 따른다.
- Tab이 입력 직후 다른 컨트롤로 포커스를 옮기는 앱에서는 문맥을 잃어
  변환이 제한될 수 있다. `AcceptsTab=true`인 편집기에서는 입력창 안에서
  검증할 수 있다.

## 호환성 붙여넣기 모드

기본값은 OFF다. 사용자가 명시적으로 켠 경우에만 직접 Unicode 입력 대신
다음 절차를 사용한다.

1. 기존 클립보드 데이터 객체와 시퀀스 번호를 메모리에 보관한다.
2. 변환문을 임시로 넣고 Ctrl+V 입력 결과를 센다.
3. 150ms 뒤 시퀀스가 그대로일 때만 기존 데이터 객체를 복원한다.
4. 다른 앱이나 사용자가 클립보드를 바꿨다면 새 값을 덮어쓰지 않는다.
5. 복원 실패를 진단 이벤트로 남기되 내용은 기록하지 않는다.

게임·보안 정책 우회 기능이 아니며 Ctrl+V가 제한된 앱에서는 실패할 수 있다.

## Compatibility Harness

`tests/Hanki.CompatibilityHarness`에는 다음 컨트롤이 있다.

- 일반 한 줄 TextBox
- `AcceptsReturn=true`, `AcceptsTab=true` 여러 줄 TextBox
- PasswordBox
- 읽기 전용 TextBox
- 빠른 입력·Backspace 수정용 TextBox
- 한글/영문 IME, Caps Lock, Shift, 숫자패드 Enter 안내

일반 권한:

```powershell
tests\Hanki.CompatibilityHarness\Run-CompatibilityHarness.ps1
```

관리자 권한은 사용자가 다음 스크립트를 직접 실행할 때만 UAC를 요청한다.

```powershell
tests\Hanki.CompatibilityHarness\Run-CompatibilityHarness-Elevated.ps1
```

## 지원 요청에 첨부할 것

- 한키 버전과 Portable/설치형 여부
- 자가 테스트 결과
- 내부 테스트 결과
- 문제가 발생한 앱 이름과 일반/관리자 권한 여부
- 개인정보를 제외한 진단 ZIP

단축어 원문, 변환문, 문서, 비밀번호, 클립보드 내용은 보내지 않는다.
