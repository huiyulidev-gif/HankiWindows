# 한키 0.1.1 테스트 보고서

테스트 일자: 2026-07-25
환경: Windows 10.0.26200, x64, .NET SDK 8.0.420, Inno Setup 6.7.3

## 결과 요약

- Debug/Release 솔루션 빌드: 경고 0개, 오류 0개
- Debug/Release 자동 테스트: 각각 31/31 통과(기존 19개 + 신규 12개)
- 0.1.1 Portable 실제 실행 및 빠른 5회 재실행: 프로세스 1개, 창 1개, 응답 정상
- 설치된 0.1.0 위에 0.1.1 사용자 단위 업그레이드: 통과, UAC 요청 없음
- 업그레이드 전후 사용자 DB 바이트와 SHA-256 동일, 시작 메뉴 바로가기와 제거 프로그램 정상 등록
- X·최소화·트레이 아이콘의 0.1.1 실제 UI 입력: 다른 전체화면 앱 때문에 자동 제어가 한키 창 활성화에 실패해 미실행
- 메모장·WPF 입력창·PasswordBox 검사는 0.1.0 회귀 결과이며 이번 패치에서 다시 실행하지 않음

## 자동 테스트

`Hanki.Core.Tests`의 31개 테스트를 Debug와 Release 구성에서 각각 실행해 모두 통과했습니다.
기존 19개는 그대로 유지했고 단일 인스턴스와 창 복원 테스트 12개를 추가했습니다.

검증 범위:

- 단축어 trim, 빈 단축어와 빈 변환 문장 거부
- 중복 단축어 거부와 대소문자 구분
- 정확한 토큰 끝 일치, 부분 일치 차단
- 한글 Unicode 단축어
- 즐겨찾기 우선 및 최신 수정순 정렬
- SQLite 설정 저장, 사용 횟수 증가
- JSON 내보내기/가져오기와 중복 이름 바꾸기
- 제외 프로세스 판정
- 변환 재진입 및 쿨다운 방지
- 첫 실행 Primary/두 번째 실행 Secondary 판정
- Secondary 활성화 신호 전송과 신호 1회당 콜백 1회
- 빠른 5중 실행의 Primary 1개 유지
- 완전 종료 후 Mutex·활성화 이벤트 정리와 새 Primary 시작
- Hidden·Minimized·이미 표시 중인 창 복원
- 닫힌 창 재생성, 동일 창 재사용, 전면 표시·Topmost fallback

| 항목 | 결과 | 비고 |

기존 수동 테스트 백업은 변경하지 않았습니다.

`안녕하세요. 문의해 주셔서 감사합니다.`만 사용했습니다.

## 비밀번호 입력 보호

테스트 전용 WPF 창 `tools/Hanki.InputTestHarness`에서 일반 TextBox, PasswordBox, 다중행 TextBox를 비교했습니다.

- 일반 TextBox와 다중행 TextBox: `;문의` + Space 정상 변환
- PasswordBox: 가짜 테스트 문자열 `;문의` 뒤 Space를 입력해도 4개의 마스킹 문자로만 남고 변환되지 않음
- UI Automation에는 실제 문자열이 아니라 마스킹 문자만 노출됨
- 로그 폴더가 생성되지 않았고 입력 문자열·변환 문장·클립보드·비밀번호 로그가 없음
- Windows 로그인 화면, UAC 보안 데스크톱, 실제 금융·계정 비밀번호 화면은 테스트하지 않음

로컬 HTML의 `<input type="password">`도 준비했지만, Chrome/Edge 전용 제어 연결이 없어 브라우저 안에서의 실제 보호 동작은 검증하지 않았습니다.

## 보안 점검

- 실행 중인 설치본 PID를 대상으로 약 1초 간격 3회 확인한 결과 TCP 연결 0개, UDP 끝점 0개였습니다.
- 실제 소스(`bin`/`obj` 제외)에서 `HttpClient`, 소켓, WebClient, Supabase, OAuth, 분석 및 광고 SDK 사용을 찾지 못했습니다.
- 명시적 외부 패키지는 `Microsoft.Data.Sqlite`뿐입니다. 테스트 프로젝트에는 MSTest와 coverlet이 있습니다.
- 비밀정보 형태의 API 키, OAuth 토큰, 클라이언트 비밀값을 찾지 못했습니다.
- 클립보드 API 사용을 찾지 못했습니다.
- 오류 로그는 시각, 정제된 기능 위치, 예외 형식만 기록하도록 구현되어 있습니다. 정상 테스트 동안 Logs 폴더 자체가 생성되지 않았습니다.
- 키보드 훅 주입 재진입과 쿨다운은 자동 테스트에 포함되어 통과했습니다.
- 앱 프로세스 종료와 제거 후 한키 프로세스가 남지 않았습니다.
- 설치 스크립트는 `PrivilegesRequired=lowest`이며 관리자 권한을 강제하지 않습니다.

짧은 로컬 관찰과 정적 소스 검사는 “모든 실행 경로에서 절대로 통신하지 않는다”는 패킷 수준의 완전한 증명은 아닙니다.

## 배포 파일

최종 파일 크기, SHA-256, Defender 결과는 최종 패키징 뒤 이 문서와 함께 기록했습니다.

| 파일 | 실제 실행 | Defender | SmartScreen |
|---|---|---|---|
| `dist/Hanki-0.1.1-win-x64.zip` | 폴더의 `Hanki.exe` 실행 및 빠른 5회 재실행 확인 | 미실행 | ZIP 안 실행 파일은 서명되지 않아 경고 가능 |
| `dist/HankiSetup-0.1.1.exe` | 0.1.0 위 업그레이드, 설치본 실행, 제거·재설치 확인 | 미실행 | 코드 서명이 없어 평판 기반 경고 가능 |

SmartScreen 또는 Defender를 끄거나 우회하지 않았습니다. 두 실행 파일의 Authenticode 상태는 `NotSigned`이며, 가짜 서명을 추가하지 않았습니다.

## 남은 제한

- Chrome/Edge의 text input, textarea, contenteditable, 주소창, 검색창은 실제 미검증입니다.
- Discord/KakaoTalk은 실제 미검증입니다.
- X→트레이→재실행, 최소화→재실행, 트레이 아이콘 좌클릭/메뉴 열기, 트레이 완전 종료의 0.1.1 실제 UI 조작은 미검증입니다.
- Windows 로그인 후 자동 실행은 미검증입니다.
- 관리자 권한 앱, 보안 데스크톱, 일부 게임·커스텀 입력창, UI Automation `TextPattern` 미지원 입력창에서는 동작하지 않을 수 있습니다.
- 코드 서명 인증서가 없어 SmartScreen 경고가 나타날 수 있습니다.
